# Airtel Device-Recovery Voice AI

A FastAPI application for managing device-recovery calling campaigns using Exotel and a Pipecat voice agent.

## Project files

### Application code (`app/`)

- **`__init__.py`** — Marks `app` as a Python package.
- **`main.py`** — Starts the FastAPI app, initializes the database, registers API routes, and exposes the health-check endpoint and Exotel media WebSocket endpoint.
- **`api.py`** — Defines endpoints for creating campaigns, importing contacts, dialing contacts, receiving Exotel call-status webhooks, and recording Pipecat conversation outcomes.
- **`config.py`** — Loads application settings from environment variables, including the database path, call provider, Exotel settings, and internal webhook token.
- **`database.py`** — Creates and manages the SQLite database, including its tables and schema migrations.
- **`services.py`** — Implements campaign and contact operations, phone-number validation, call-eligibility checks, Exotel dialing, media-token verification, status callback processing, and outcome storage.
- **`voice_agent.py`** — Handles Exotel's bidirectional audio WebSocket and runs the Pipecat pipeline using Deepgram for speech-to-text, OpenAI for the language model, and Cartesia for text-to-speech.

### Project-root files

- **`pyproject.toml`** — Defines project metadata, the Python version requirement, dependencies, package discovery, and test configuration.
- **`README.md`** — Describes the project and explains the purpose of its files.
- **`.gitignore`** — Lists files Git should ignore, such as secrets, local databases, virtual environments, and generated files.
- **`.env`** — Local environment variables and API credentials. Keep this file private and do not commit it.

### Local/generated files

- **`data/campaigner.db`** — Local SQLite database for campaigns, contacts, call attempts, telephony events, and conversation outcomes. The application creates the database at the configured path when it starts.
- **`airtel_device_recovery.egg-info/`** — Generated Python packaging metadata. It may contain `PKG-INFO`, `SOURCES.txt`, `dependency_links.txt`, `requires.txt`, and `top_level.txt`; these are normally generated by packaging tools and do not need to be committed.
- **`__pycache__/`, `*.pyc`, `.venv/`, `venv/`** — Generated Python cache files and local virtual environments; do not commit them.

## How the application works

1. `main.py` starts FastAPI and initializes the database.
2. `api.py` receives requests to create campaigns, import contacts, or start calls.
3. `services.py` validates contacts, checks call eligibility, and performs the calling and persistence operations.
4. For live calls, the application requests a call through Exotel and provides a public media WebSocket URL.
5. Exotel connects to the `/media` WebSocket, where `voice_agent.py` runs the Pipecat conversation pipeline.
6. Exotel sends status updates to `/webhooks/exotel/status`.
7. A conversation outcome can be sent to `/internal/pipecat/outcomes` and saved in the database.

## Run locally

Use Python 3.11 or newer. From the project root, install dependencies and start the application:

```bash
pip install -e .
uvicorn app.main:app --reload
```

## Configuration notes

- `CALL_PROVIDER=mock` selects the mock calling path; `CALL_PROVIDER=exotel` selects Exotel dialing.
- Live calls require the relevant Exotel settings and a publicly reachable `PUBLIC_BASE_URL`.
- The voice agent requires `OPENAI_API_KEY`, `DEEPGRAM_API_KEY`, `CARTESIA_API_KEY`, and `CARTESIA_VOICE_ID`.
- `INTERNAL_WEBHOOK_TOKEN` is used to protect internal outcome requests and sign media-stream tokens.
- Contacts are only eligible for dialing when their consent status is `granted` or `service_basis` and they have not opted out
